重点、公式与解读

本章重点
数据转换先检查语义，再校验格式：轨迹边界、同步、坐标、单位和统计。
核心公式
ã = (a−μ训练) / max(σ训练, ε)
怎么理解
ε 用于避免除零；若上游使用其他归一化，必须按原实现。训练统计只能从训练划分拟合，且与 checkpoint 一起保存。
阅读备注
数据格式字段一致不代表动作语义一致；不要跨 episode 拼接窗口。
动手自测
编写检查器输出缺帧、越界动作、重复轨迹与无效时间戳。

先定义一条轨迹

一条 episode 应包含按时间排序的观测、动作、语言任务描述、终止信号与必要的元数据。多相机图像和机器人状态应对齐到同一时间基准。检查记录的是动作下发时间还是执行反馈时间，错位一个控制周期就可能改变监督关系。

转换 RLDS 和 LeRobot 数据时的检查

  1. 统计 episode 数、总步数、帧率、相机名、动作维度和缺失字段。
  2. 随机抽取完整轨迹，把视频、状态与动作曲线放在一起检查。
  3. 保留终止与截断的区别，窗口采样不能穿过 episode 边界。
  4. 显式记录图像的 RGB/BGR、数值范围、裁剪和旋转。
  5. 保存转换程序版本、源文件校验值和字段映射。

归一化统计量只来自训练集

均值方差或分位数统计量必须随 checkpoint 保存。推理时使用同一套统计量逆变换动作。不同机器人或数据源可能需要各自的统计键，不能把单位和动作空间不同的数值直接拼接。

防止数据泄漏

随机按帧拆分会把同一轨迹的近邻放进训练和测试。应按 episode 划分，并按研究目标进一步隔离物体、场景、任务或本体。语言改写不能自动视为全新任务。

交付清单

提供 data card：来源与许可、采集方式、轨迹数量、成功失败比例、划分规则、预处理、已知偏差和适用范围。公布转换代码不代表你有权重新分发原数据。
