作品集的共同结构

README 写问题、读者与运行步骤；记录环境版本、数据来源和许可；展示基线、指标、失败与个人贡献；附自动化测试或验收脚本。视频可展示行为，但必须有可重复的文字和结果。

六类示例

  • 算法：受控对照、消融、失败轨迹与资源预算。
  • 测试评测：协议、用例、原始记录和缺陷闭环。
  • 数据运营：SOP、抽检、覆盖和质量分析。
  • 软件平台：接口、异常恢复、性能与部署说明。
  • 硬件：图纸、计算、工况、测量与迭代。
  • 产品交付：调研、PRD、PoC、验收及复盘。

简历表达

写“在固定 X 条件下，相比基线 Y，将指标由 A 改为 B；负责 Z”，而不是只有“熟悉大模型、精通 ROS”。没有测过的提升不能写；团队贡献与个人贡献分开。模拟项目、公开数据和企业经历明确区分。

公开边界

不公开企业私有数据、客户场景、账号、日志和受限代码。用合成数据、接口说明与脱敏流程展示方法，遵守原许可及保密义务。
