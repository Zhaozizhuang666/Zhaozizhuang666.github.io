LINUX SYSTEMS

Linux 学习资料与命令手册

按主题查找常用命令、参数、输出含义和操作注意点，覆盖 Shell、系统管理、存储、网络、安全、性能、容器与内核。

历史知识点：CentOS 5、SysV、GRUB/LILO、RPM/YUM、ifconfig/netstat、at/cron、/proc。

现代知识点：systemd/journald、iproute2、nftables、cgroup v2、namespaces、SELinux/AppArmor、容器与 eBPF。

推荐学习路线

  1. 命令行与文件系统

    掌握终端、路径、FHS、文件查找、文本处理、管道、重定向、引号和环境变量；读懂基础 Bash 脚本。

    重点：Bash、Coreutils、man-pages、权限与链接。

  2. 用户、权限与进程

    理解用户组、sudo、文件权限、ACL、进程状态、信号、作业控制，以及 /proc 和 /sys 的诊断用途。

    重点：最小权限、进程生命周期、命令退出码和日志。

  3. 启动、服务与日志

    学习 UEFI/GRUB 启动路径、systemd unit、依赖、目标、服务状态和 journald；用日志和服务状态解释启动故障。

    重点：systemctl、journalctl、启动依赖和恢复流程。

  4. 存储与文件系统

    掌握块设备、GPT 分区、挂载、/etc/fstab、swap、LVM、软件 RAID、ext4/XFS/Btrfs 的用途和基本检查；了解 LUKS 加密。

    重点：设备识别、容量、inode、I/O、备份与恢复。

  5. 网络与防火墙

    从 TCP/IP、路由、DNS、端口和套接字开始，学习 NetworkManager、iproute2、ss、抓包、nftables 及发行版防火墙管理。

    重点：分清链路、路由、解析、监听、策略和应用层故障。

  6. 系统安全

    建立 SSH、sudo、补丁、密钥、审计和安全基线；按发行版了解 SELinux 或 AppArmor，并理解 Linux capabilities、namespaces、seccomp 的边界。

    重点：默认拒绝、最小权限、可审计变更和回滚。

  7. 观测与性能

    结合负载、采样周期和日志观察 CPU、内存、磁盘、网络与进程；逐步学习 PSI、cgroup v2、perf 和 eBPF 工具。

    重点：先建立基线，再定位饱和资源与因果关系。

  8. 自动化、容器与虚拟化

    用可审查的 Bash 或 Ansible 重复配置；理解镜像、rootless 容器、Podman、systemd 集成、KVM/libvirt，以及容器依赖的 namespaces 与 cgroups。

    重点：幂等性、凭据保护、资源限制和运行时隔离。

  9. 内核与深入排障

    从系统调用、内核日志、模块、设备、文件系统和网络栈入手；需要内核开发时再继续阅读源码、追踪点和构建文档。

    重点：以 Linux Kernel Documentation 和对应版本源码为准。

1. 系统信息与 Shell 基础

先确认当前系统和命令来源。Linux 发行版之间的包管理器、服务名称、配置路径和可用参数并不完全相同。

命令作用与结果
cat /etc/os-release显示发行版名称和版本，常见字段有 ID、VERSION_ID。
uname -r
uname -a		查看内核版本；-a 同时显示内核、主机架构等信息。
hostnamectl在 systemd 系统上查看主机名、操作系统和硬件架构；精简容器中可能不存在。
man find
find --help		前者打开手册页，后者显示命令帮助。手册中按 /关键词 搜索，按 q 退出。
type -a python
command -v python3		查看命令是别名、函数、内建命令还是可执行文件，并定位当前会运行的路径。
printf '%s\n' "$HOME"显示变量值。双引号保留变量展开并保护空格；单引号保留字面内容。
grep -n 'error' app.log管道用 | 把前一个命令的标准输出交给后一个命令；用 > 覆盖文件、>> 追加。
command_a && command_b只有前一条成功（退出码为 0）才运行后一条；; 不检查成功与否。用 echo $? 查看上一条命令退出码。
#!/usr/bin/env bash
set -euo pipefail
src=${1:?用法: script.sh SOURCE_DIR}
[[ -d "$src" ]] || { printf '目录不存在: %s\n' "$src" >&2; exit 1; }
find "$src" -type f -name '*.log' -print

set -e 对未处理的失败退出，-u 拒绝未定义变量，pipefail 传播管道失败。复杂脚本仍需显式处理预期错误和清理动作。

printf '%s\n' "当前用户: $USER"
type -a ls
grep -n 'ERROR' app.log | tail -20
some_command >output.txt 2>&1
echo "exit=$?"

不要把密码、令牌或私钥直接写进命令参数或 Shell 历史记录。长管道调试时可分步执行；Bash 脚本可用 set -o pipefail 让管道报告中间命令失败。

2. 目录、文件与文本

命令作用与示例
pwd显示当前工作目录。相对路径以这里为起点；~ 表示当前用户主目录。
ls -lah
ls -lt		长格式显示隐藏文件、人类可读大小；第二条按修改时间排序。注意目录的权限字符不等于文件内部权限。
mkdir -p ~/work/demo递归创建目录；父目录已存在时不报错。
cp -a src/ backup/
mv -i old new		cp -a 尽量保留权限、时间和符号链接；mv -i 覆盖前询问。
file report.bin
stat report.bin		识别文件类型；显示大小、权限、所有者、inode 和时间戳等元信息。
find . -type f -name '*.log'从当前目录递归查找普通文件。单引号避免 Shell 抢先展开 *。
find /var/log -type f -mtime -1查找最近 24 小时内修改的普通文件；搜索权限不足时会出现 Permission denied。
grep -RIn --include='*.conf' 'Listen' /etc递归搜索文本；-n 显示行号、-i 忽略大小写。对大型目录缩小搜索范围。
less app.log
tail -n 100 -f app.log		分页查看文件；持续跟踪末尾新增内容。日志轮转后可用 tail -F 重新跟踪同名文件。
wc -l access.log统计行数；wc -w 统计词数，wc -c 统计字节。
sort names.txt | uniq -c | sort -nr排序后统计重复行，再按计数从高到低排序。uniq 只合并相邻重复行，所以前面通常需要 sort。
cut -d: -f1 /etc/passwd按冒号分隔字段并取第一列。处理复杂 CSV 时不要把 cut 当作完整 CSV 解析器。
find ./logs -type f -name '*.log' -mtime -7 -print
grep -RIn --include='*.conf' 'timeout' ./config
tail -F /var/log/syslog
du -ah ./data | sort -h | tail -20

GNU/Linux 常见 grep -R、sed -i 和 GNU 参数；macOS/BSD 工具的选项可能不同。批量改写前先用不修改文件的模式预览结果。

3. 用户、组与权限

命令作用与结果
id
id alice		查看当前用户或指定用户的 UID、主组和附加组。
getent passwd alice
getent group sudo		通过系统名称服务查询用户或组，比只读本地 /etc/passwd 更能反映 LDAP 等目录配置。
sudo -l查看当前账号被允许执行的 sudo 命令；不代表可以安全执行所有管理员命令。
chmod 640 file八进制权限：4=读、2=写、1=执行。640 表示所有者读写、组只读、其他人无权限。
chmod u+x script.sh符号方式为所有者增加执行位；g-w 表示移除组写权限。
umask
umask 027		查看或设置新建文件/目录权限掩码。027 常使文件默认为 640、目录默认为 750（受程序创建模式影响）。
chown alice:dev file修改所有者和组，需要相应权限。递归 -R 可能影响大量文件，执行前检查目标路径。
getfacl shared/
setfacl -m u:alice:rwx shared/		读取 ACL 或为指定用户增加访问规则；用 getfacl 复查最终权限。
useradd -m alice
passwd alice		管理员创建带主目录的用户并设置密码。Debian/Ubuntu 也常用交互式 adduser。
usermod -aG dev alice把用户追加到附加组。必须保留 -a；漏掉它可能替换该用户已有的附加组。
id
stat -c '%A %a %U:%G %n' ./script.sh
chmod u+x ./script.sh
sudo -l

rwx 对普通文件表示读写执行；对目录分别表示列目录、创建/删除条目和进入/遍历目录。目录可遍历不等于能读取所有文件。

4. 进程、systemd 服务与日志

命令作用与示例
ps -eo pid,ppid,user,stat,%cpu,%mem,cmd --sort=-%cpu | head按 CPU 使用率查看进程；PID 是进程号，PPID 是父进程，STAT 表示状态。
pgrep -a sshd
pstree -ap		按名称查 PID 并显示命令行；查看进程父子关系。进程名称和服务名称可能不同。
kill -TERM 1234请求进程正常退出并允许清理。确认 PID 属于目标进程；KILL 不可捕获，应是最后手段。
jobs -l
bg %1
fg %1		查看、后台继续或切回当前 Shell 作业。终端关闭后后台进程不一定继续运行。
systemctl status ssh查看服务状态和最近日志行。服务单元名因发行版而异，例如 Debian 常用 ssh、RHEL 常用 sshd。
systemctl is-enabled ssh检查是否配置为开机启动；“enabled”不代表当前正在运行。
systemctl list-units --type=service --state=failed列出失败服务。先读状态和日志，再决定是否重启。
sudo systemctl start nginx
sudo systemctl enable --now nginx		分别立即启动服务，或设置开机启动并立即启动。修改运行状态前确认服务名和维护窗口。
sudo systemctl daemon-reload重新读取 unit 文件。仅在修改 unit 配置后运行；它本身不会重启服务。
journalctl -u ssh -b查看本次启动以来指定服务的日志；用 -b -1 查看上次启动。
journalctl -u ssh -f
journalctl --since '1 hour ago'		实时跟踪服务日志；或按时间过滤最近一小时记录。
systemctl cat ssh显示 unit 文件和覆盖配置，适合确认实际加载的服务定义。
systemctl status ssh --no-pager
journalctl -u ssh -b --no-pager -n 100
systemctl is-active ssh
systemctl is-enabled ssh

修改服务状态前检查服务名、依赖和远程连接方式。重启网络或 SSH 可能切断当前会话；先准备控制台或回滚方法。

5. 软件包与仓库（按发行版选择一组）

Debian / Ubuntu：APT 与 dpkg

apt search nginx
apt show nginx
sudo apt update
sudo apt install nginx
dpkg -L nginx
dpkg -S /usr/sbin/nginx

apt update 刷新软件包索引，不会升级系统；install 安装软件。dpkg -L 列出包文件，-S 查询文件归属。

Fedora / RHEL：DNF 与 RPM

dnf search nginx
dnf info nginx
sudo dnf install nginx
rpm -qi nginx
rpm -ql nginx
rpm -qf /usr/sbin/nginx

查看仓库和包元信息后再安装。RPM 查询已安装包；软件包签名和仓库来源应遵循发行版安全策略。

卸载命令同样会改变系统状态：APT 用 sudo apt remove <包名>，DNF 用 sudo dnf remove <包名>。执行前阅读将被移除的依赖清单。

不要在同一系统混用不同发行版的仓库或包管理流程。生产主机安装前，检查包来源、签名、版本和依赖变更。

6. 磁盘、挂载与文件系统

命令作用与检查点
lsblk -o NAME,SIZE,FSTYPE,TYPE,MOUNTPOINTS列出块设备、文件系统、类型和挂载点；先确认目标磁盘及其分区关系。
sudo blkid
findmnt		读取块设备 UUID/文件系统标识；显示当前挂载树和挂载选项。
df -hT
df -i		查看文件系统空间、类型和 inode 使用率。空间充足但 inode 用尽也会无法创建文件。
du -xhd1 /var 2>/dev/null | sort -h查看 /var 下一层目录占用；-x 不跨文件系统。macOS/BSD 的 du 参数可能不同。
findmnt --verify检查 /etc/fstab 配置语法；挂载前仍要核对设备 UUID、目标路径和启动影响。
sudo mount /dev/sdb1 /mnt/test将指定分区挂载到目录。确认设备、文件系统和挂载选项；卸载用 sudo umount /mnt/test。
sudo pvs
sudo vgs
sudo lvs		只读查看 LVM 物理卷、卷组和逻辑卷布局。
sudo mdadm --detail /dev/md0查看 Linux 软件 RAID 阵列状态；设备名按实际阵列替换。

高风险写操作：mkfs、parted、fdisk 写入、dd、破坏性 fsck、LVM/RAID 初始化会改变或覆盖数据。先用 lsblk -f、blkid、findmnt 核对设备，并在可丢弃虚拟机练习。

7. 网络与 DNS 诊断

命令作用与诊断顺序
ip -br link
ip -br addr		简洁查看网卡链路状态和 IP 地址；DOWN 表示接口链路未启用或未连接。
ip route
ip route get 1.1.1.1		查看路由表，并查询目标地址将走哪个网卡、网关和源 IP。
ss -lntup查看 TCP/UDP 监听端口及进程；-l 监听、-n 数字、-t TCP、-u UDP、-p 进程。
getent ahosts example.com通过系统名称服务解析域名；结果为空时检查 DNS 配置、网络和本机解析缓存。
resolvectl status在使用 systemd-resolved 的系统上查看 DNS 服务器和每链路设置；其他系统可能没有此命令。
curl -I --max-time 10 https://example.com只请求 HTTP 响应头并设置超时。观察 DNS、连接、TLS 和 HTTP 状态码。
dig +short example.com使用 DNS 工具查询记录；dig 可能需要单独安装，getent 更接近系统应用实际解析路径。
sudo tcpdump -ni any -c 50 port 53抓取最多 50 个 DNS 相关数据包；抓包需要权限，注意数据隐私并限制过滤范围。
nmcli device status
nmcli connection show		在 NetworkManager 系统上查看设备和连接配置，不会修改网络。
ip -br addr
ip route
getent ahosts example.com
curl -I --max-time 10 https://example.com
ss -lntup

排障顺序：链路和地址 → 默认路由 → DNS → 目标端口监听/防火墙 → 应用响应。修改路由或防火墙前，确认不会切断 SSH 和远程管理通道。

8. 资源监控与性能

命令观察内容
uptime系统运行时间、登录用户数和 1/5/15 分钟平均负载；负载需结合 CPU 核数理解。
free -h查看内存和 swap；Linux 会把空闲内存用于缓存，优先观察 available，不要只看 free。
vmstat 1 5每秒采样一次，共 5 次，观察运行队列、内存、交换、块 I/O 和 CPU。首行统计自开机以来平均值，后续行才是采样区间。
iostat -xz 1 3查看设备 I/O 延迟、吞吐和利用率；通常由 sysstat 包提供。
mpstat -P ALL 1 3按 CPU 核观察利用率和中断负载；通常由 sysstat 包提供。
pidstat -dru 1 3按进程查看 CPU、内存和 I/O 使用；同属 sysstat 工具集。
sar -n DEV 1 3查看网卡流量等历史/实时统计；数据采集服务可能需单独启用。
dmesg -T | tail -100读取内核环形缓冲区近期消息；系统也可能通过 journal 保存内核日志。
cat /proc/pressure/{cpu,memory,io}在支持 PSI 的内核上查看资源压力；数值表示任务因资源争用而停顿的时间比例。

先记录时间范围、负载和基线，再比较 CPU、内存、I/O、网络与日志。一次采样或单个百分比不能单独证明根因；高延迟、队列和应用症状需要相互印证。

9. 压缩、同步与计划任务

命令作用与示例
tar -tf archive.tar.gz只列出归档内容；解压前用它检查文件路径。
tar -czf backup.tar.gz ./project创建 gzip 压缩归档；-c 创建、-z gzip、-f 指定文件。
tar -xzf backup.tar.gz -C /tmp/restore解压到指定目录。先确认目标目录和归档路径，避免覆盖现有文件。
rsync -av --dry-run src/ host:/backup/src/预览同步计划；确认方向、尾部斜杠和删除行为后再移除 --dry-run。
crontab -l
crontab -e		查看或编辑当前用户 cron。格式为“分 时 日 月 星期 命令”；cron 的 PATH 和环境变量通常比交互 Shell 更少。
systemctl list-timers --all查看 systemd 定时器及下次触发时间；服务系统日志可用 journalctl -u name.timer / name.service 检查。
atq
atrm <任务号>		查看或删除一次性 at 任务；服务和命令依赖发行版配置。
tar -czf config-$(date +%F).tar.gz ./config
tar -tf config-2026-11-26.tar.gz
rsync -av --dry-run ./data/ user@host:/srv/data/

10. 安全、SSH 与容器

命令作用与注意点
ssh -v user@host以详细模式诊断 SSH 握手和密钥选择；输出可能包含主机名等环境信息，分享前先检查。
ssh-keygen -t ed25519 -C 'workstation'生成 SSH 密钥对；私钥留在本机并设置口令，不要复制到聊天、仓库或服务器日志。
sudo -l
sudo -v		检查授权规则或刷新 sudo 凭据缓存；不要用 root 运行来源不明的脚本。
getenforce
sestatus		在 SELinux 系统上查看强制状态和策略；不要用关闭 SELinux 作为通用排障方案。
aa-status在 AppArmor 系统上查看配置文件与进程状态；不同发行版可能只默认启用其中一种 MAC 系统。
sudo nft list ruleset读取 nftables 规则集。变更规则前导出当前配置并确保有带外控制台。
podman ps -a
podman images		查看 rootless Podman 容器和镜像；容器用户与宿主用户的 UID 映射可能不同。
podman logs <容器>
podman inspect <容器>		查看容器日志和配置。日志及 inspect 输出可能包含环境变量，不要未经检查就公开。
podman exec -it <容器> sh进入容器交互检查；容器里做的修改未必持久，持久数据应使用明确的 volume。

基础安全习惯：及时安装签名可信的更新、最小权限、SSH 密钥保护、备份配置、留存审计与日志，并在虚拟机先验证变更。

11. 命令排障顺序

遇到故障先收集证据，不急着重启或删除文件。记录发生时间、完整错误、最近变更、系统版本和受影响范围。

# 1. 确认系统与时间
cat /etc/os-release
date -Is

# 2. 确认服务与日志
systemctl status <service> --no-pager
journalctl -u <service> -b --no-pager -n 100

# 3. 确认资源与磁盘
uptime
free -h
df -hT
df -i

# 4. 确认网络和监听
ip -br addr
ip route
ss -lntup

把占位符替换为实际服务名；先确认这些检查命令可用，再按证据深入到对应子系统。收集日志时注意过滤凭据、个人信息和内部地址。
